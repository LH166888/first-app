## 一、背景与目标

项目从「纯车榜」演进为多模块平台（车榜 / 菜单 / 工具箱）。第 0+1 步已完成平台外壳 + 目录归位（`modules/` + `shared/`），第 2 步接入**菜单模块**——这是第一个真正的「新业务功能」，既验证模块化架构扩展性，也是门户首页「菜单推荐」内容的真实来源。

**核心目标**：
1. 用户能创建「菜谱」，上传图片、填写食材与制作步骤。
2. 其他用户能浏览菜谱、下「点单」（表达「想吃这道菜」），菜谱作者在「我收到的点单」看到需求，点单人在「我下的点单」追踪。
3. 图片上传接入 Cloudflare R2（S3 兼容存储），前端预签名直传。
4. 后端新增 `menus` / `menu_ingredients` / `menu_steps` / `orders` 表及对应 Controller，路由按 `prefix('menu')` 分组、`auth:sanctum` 鉴权。
5. 前端遵循模块化：`modules/menu/` 完整自洽（routes.js / MenuLayout.vue / views / components / api）。

## 二、产品定位与核心概念（待你确认）

架构文档的用语「菜单」在中文语境有歧义（餐厅的 menu 菜单 vs 某一道菜的菜谱 recipe）。结合路由设计（`/menu/create` 创建菜单、`/menu/:id` 菜单详情）与点单逻辑，我理解的产品模型是：

- **「菜单」= 一道菜的菜谱**（recipe），而非「很多道菜的集合」。用户创建的是「糖醋里脊」「宫保鸡丁」这种单品菜谱，包含名称、图片、食材清单、制作步骤。
- **「点单」= 对某道菜表达兴趣**。点单是社交动作：用户 A 创建了「糖醋里脊」，用户 B 看到后点击「点单」，记录一条 order（点单人 B、目标菜谱「糖醋里脊」、时间）。B 在「我下的点单」看到自己点过的菜，A 在「我收到的点单」看到有谁想吃自己的菜。点单不涉及支付、配送，纯兴趣表达 + 社交展示。

**请明确**：这个理解是否正确？如果「菜单」实际是「多道菜的合集」（用户创建一份菜单、包含多道菜），或「点单」有其他业务含义（比如实际下单购买食材、或预约制作时间），需要你纠正后我才能准确建模。

## 三、功能范围

基于上述理解（待确认），本期范围：

### 3.1 菜谱管理（CRUD）
- **我的菜单**（`/menu`）：当前用户创建的菜谱列表，卡片展示（图片 + 菜名 + 创建时间），点击进详情。
- **创建菜单**（`/menu/create`）：表单——菜名（必填）、图片上传（单图，R2 直传）、食材清单（动态行，每行：名称 + 用量 + 可选图标/emoji）、制作步骤（动态行，每行：步骤描述，支持多行文本）。提交后跳回「我的菜单」。
- **菜单详情**（`/menu/:id`）：展示菜谱完整信息（图片大图 + 菜名 + 食材表格 + 步骤列表）+ 作者信息 + 创建时间。**若是别人的菜**显示「点单」按钮（点击后记录 order、按钮变「已点单」不可重复点），**若是自己的菜**显示「编辑」「删除」（删除需二次确认）。
- **编辑菜单**（`/menu/:id/edit` 或复用 create 页 + `?id=xx`）：回填现有数据，提交更新。

### 3.2 点单明细
- **点单明细**（`/orders`）：Tab 切换「我收到的」「我下的」。
  - **我收到的**：别人对我的菜谱下的点单，列表显示：点单人、菜名、点单时间，点击菜名进菜谱详情。
  - **我下的**：我对别人菜谱下的点单，列表显示：菜谱作者、菜名、点单时间，点击菜名进菜谱详情。

### 3.3 图片上传（R2 直传）
- 前端调后端 `POST /menu/upload-url`（传 filename、content_type）获取预签名 PUT URL + headers + key。
- 前端用原生 fetch 直传文件到 R2（不带 Sanctum token）。
- 成功后表单提交时只传 `image_key`（如 `menu/2026/09/uuid-xxxx.jpg`），不传完整 URL。
- 详见 [[图片上传方案-A-CloudflareR2]]。

### 3.4 食材图标/emoji
- 架构文档提到「食材下拉+图标」。暂定方案：前端内置常见食材 emoji map（如 `{鸡肉:'🍗', 猪肉:'🥓', 番茄:'🍅', ...}`），输入食材名时模糊匹配 + 自动附 emoji；不在 map 里的食材无图标，不阻塞流程。**是否需要后端表 `ingredients` 预设食材库 + 自定义上传图标**？先用前端 emoji 兜底，后续可扩展。

## 四、数据模型（提案）

### 4.1 表结构

**`menus`**（菜谱主表）
```sql
id               bigint unsigned primary key auto_increment
user_id          bigint unsigned not null          -- 创建者（关联 users.id）
name             varchar(100) not null              -- 菜名
image_key        varchar(255) nullable              -- R2 key（如 menu/2026/09/uuid.jpg）
created_at       timestamp
updated_at       timestamp
index(user_id)
```

**`menu_ingredients`**（食材清单，一对多）
```sql
id               bigint unsigned primary key auto_increment
menu_id          bigint unsigned not null          -- 关联 menus.id
name             varchar(50) not null              -- 食材名（如「鸡胸肉」）
amount           varchar(50) nullable              -- 用量（如「300g」「2个」）
sort_order       tinyint unsigned default 0        -- 显示顺序
created_at       timestamp
updated_at       timestamp
index(menu_id)
foreign key(menu_id) references menus(id) on delete cascade
```

**`menu_steps`**（制作步骤，一对多）
```sql
id               bigint unsigned primary key auto_increment
menu_id          bigint unsigned not null          -- 关联 menus.id
step_number      tinyint unsigned not null         -- 步骤序号（1,2,3...）
description      text not null                     -- 步骤描述
created_at       timestamp
updated_at       timestamp
index(menu_id)
foreign key(menu_id) references menus(id) on delete cascade
unique(menu_id, step_number)
```

**`orders`**（点单记录）
```sql
id               bigint unsigned primary key auto_increment
menu_id          bigint unsigned not null          -- 目标菜谱
user_id          bigint unsigned not null          -- 点单人
created_at       timestamp
updated_at       timestamp
index(menu_id)
index(user_id)
foreign key(menu_id) references menus(id) on delete cascade
foreign key(user_id) references users(id) on delete cascade
unique(menu_id, user_id)  -- 同一用户对同一菜谱只能点单一次
```

### 4.2 待确认的数据建模决策

1. **单图 vs 多图**：当前设计 `menus.image_key` 单字段 = 一道菜一张主图。若需多图（成品图 + 过程图），需改为关联表 `menu_images(menu_id, image_key, sort_order)`。
2. **食材表独立 vs 内嵌**：当前 `menu_ingredients` 每次创建菜谱时自由输入食材名。若需「食材库」（预设常见食材 + emoji/图标 + 营养信息），需建 `ingredients` 主表 + `menu_ingredients` 改为关联表。暂按自由输入设计。
3. **点单状态**：当前 `orders` 表只记录「谁点了谁的菜」，无状态字段。若后续需「作者接单 / 拒绝 / 完成」流程，需加 `status` enum('pending','accepted','rejected','completed')。本期先做最简版（点单即记录，无后续状态流转）。

## 五、API 设计（提案）

**路由前缀**：`Route::prefix('menu')->middleware('auth:sanctum')->group(...)`（所有菜单相关接口需登录）

### 5.1 菜谱 CRUD（MenuController）

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| GET | `/menu` | 我的菜单列表 | - | `{menus: [{id, name, image_key, created_at}, ...]}` |
| POST | `/menu` | 创建菜谱 | `{name, image_key?, ingredients:[{name,amount}], steps:[{description}]}` | `{menu: {...}}` |
| GET | `/menu/{id}` | 菜谱详情 | - | `{menu: {id, name, image_key, user: {id,name}, ingredients:[...], steps:[...], is_owner:bool, has_ordered:bool, orders_count:int}}` |
| PUT | `/menu/{id}` | 更新菜谱 | 同 POST | `{menu: {...}}` |
| DELETE | `/menu/{id}` | 删除菜谱 | - | `{message:'ok'}` |

**说明**：
- `GET /menu/{id}` 响应包含 `is_owner`（是否当前用户创建）、`has_ordered`（当前用户是否已点单）、`orders_count`（总点单数）供前端渲染按钮状态。
- `POST /menu` 和 `PUT /menu/{id}` 接收 `ingredients` 和 `steps` 数组，后端事务内批量插入/更新关联表（先删旧记录再插新，或 upsert）。

### 5.2 图片上传（MenuController 或 UploadController）

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | `/menu/upload-url` | 获取预签名 URL | `{filename: 'dish.jpg', content_type: 'image/jpeg'}` | `{upload_url, headers: {'Content-Type':...}, key: 'menu/2026/09/uuid.jpg', public_url?: '...'}` |

**说明**：详见 [[图片上传方案-A-CloudflareR2]]。后端生成 key（`menu/{year}/{month}/{uuid}-{sanitized_filename}`）、调 `Storage::disk('r2')->temporaryUploadUrl($key, now()->addMinutes(10))` 返回预签名 PUT URL。前端直传成功后，表单提交时只传 `key`。

### 5.3 点单（OrderController）

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | `/menu/{menuId}/order` | 对菜谱点单 | - | `{order: {id, menu_id, user_id, created_at}}` |
| DELETE | `/menu/{menuId}/order` | 取消点单 | - | `{message:'ok'}` |

**说明**：
- `POST` 时检查 `menu_id` 是否存在、是否自己的菜（不能给自己点单）、是否已点过（unique 约束）。
- `DELETE` 时检查是否当前用户的点单。

### 5.4 点单明细（OrderController）

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| GET | `/orders/received` | 我收到的点单 | - | `{orders: [{id, menu: {id,name,image_key}, user: {id,name}, created_at}, ...]}` |
| GET | `/orders/placed` | 我下的点单 | - | `{orders: [{id, menu: {id,name,image_key,user:{id,name}}, created_at}, ...]}` |

**说明**：
- `received`：查 `orders` where `menu.user_id = 当前用户`，关联 menu + 点单人 user。
- `placed`：查 `orders` where `user_id = 当前用户`，关联 menu + 菜谱作者 menu.user。

**路由定义示例**（`routes.js`）：
```js
import MenuLayout from './MenuLayout.vue'
import MyMenusView from './views/MyMenusView.vue'
import MenuCreateView from './views/MenuCreateView.vue'
import MenuDetailView from './views/MenuDetailView.vue'
import OrdersView from './views/OrdersView.vue'

  {
    path: '/menu',
    component: MenuLayout,

      { path: 'create', name: 'menu-create', component: MenuCreateView },
      { path: ':id', name: 'menu-detail', component: MenuDetailView },
    ],
  },
  {
    path: '/orders',
    name: 'orders',
    component: OrdersView,
    meta: { requiresAuth: true },
  },

```

**MenuLayout.vue 要点**：
- 子头内容：`<router-link to="/menu" class="logo">🍽️ 菜单</router-link>` + nav 链接（我的菜单 `/menu`、创建 `/menu/create`、点单明细 `/orders`）。

## 七、图片上传集成（R2）

详见 [[图片上传方案-A-CloudflareR2]]，此处摘要关键步骤：

### 7.1 后端（需单独确认后执行）
1. **依赖**：`composer require league/flysystem-aws-s3-v3`（Laravel 已内置 AWS S3 适配器，只需 Flysystem S3 driver）。
2. **配置**：`config/filesystems.php` 新增 `'r2'` disk：
   ```php
   'r2' => [
       'driver' => 's3',
       'key' => env('AWS_ACCESS_KEY_ID'),
       'secret' => env('AWS_SECRET_ACCESS_KEY'),
       'region' => env('AWS_DEFAULT_REGION', 'auto'),
       'bucket' => env('AWS_BUCKET'),
       'endpoint' => env('AWS_ENDPOINT'),
       'use_path_style_endpoint' => true,
       'throw' => false,
   ],
   ```
3. **.env**：补充变量（真实值从 R2 控制台获取，不由我填）：
   ```
   FILESYSTEM_DISK=r2
   AWS_ACCESS_KEY_ID=<R2_Access_Key_ID>
   AWS_SECRET_ACCESS_KEY=<R2_Secret_Access_Key>
   AWS_DEFAULT_REGION=auto
   AWS_BUCKET=<你的R2 bucket名>
   AWS_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
   R2_PUBLIC_BASE_URL=https://<bucket>.r2.dev  # 或自定义域名 https://img.aihhyy.cn
   ```
4. **Migration**：`menus` 表已在上文数据模型包含 `image_key varchar(255) nullable`。
5. **Controller**：`MenuController` 新增 `uploadUrl()` 方法生成预签名 URL（逻辑见 R2 文档）。

### 7.2 前端
- **组件**：`ImageUploader.vue`，封装「选择文件 → 调 `/menu/upload-url` → fetch PUT 直传 R2 → emit `@uploaded` 返回 key」流程。
- **表单集成**：`MenuCreateView` 引入 `ImageUploader`，监听 `@uploaded` 更新 `form.image_key`，提交时只传 key。
- **展示**：`MenuDetailView` / `MenuCard` 拼接公开 URL：`const imgUrl = imageKey ? `${R2_PUBLIC_BASE_URL}/${imageKey}` : '/default-dish.jpg'`（前端环境变量或写死）。

### 7.3 待确认
- **公开访问**：R2 bucket 是否配置公开读（推荐），或用 CDN + 自定义域名 `img.aihhyy.cn`？
- **图片规格**：是否限制尺寸（如 ≤2MB、宽高 ≤1920px）、是否需后端裁剪/压缩？暂不做服务端处理，前端提示用户「建议上传 ≤2MB 的 JPG/PNG」。
